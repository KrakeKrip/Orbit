# Orbit — активный продуктовый план

Приоритет изменён пользователем 2026-10-12: сначала локальные приложения iOS/macOS, затем возможные синхронизация и веб-клиент. Этот документ заменяет web-first MVP. Прежние требования сохранены в docs/web-baseline-2026-10-12/PRODUCT.md; веб-реализация TASK-001–008 остаётся принятой, но не определяет критерии нативного релиза.

## Первый полезный релиз

Персональное SwiftUI-приложение без регистрации и сервера, с локальным постоянным хранилищем. Работает без сети. Русский интерфейс, native navigation/accessibility, системные light/dark темы. Целевые платформы iOS и macOS; данные пока независимы на каждом устройстве, общей синхронизации нет.

Последовательность: рабочий Inbox → редактирование/удаление → локальные проекты → civil планирование, Today/Upcoming → проверка на iPhone и Mac. Поиск, notes/priority/subtasks/recurrence выдавать позже отдельными небольшими задачами; не включать весь прежний web MVP в первый native TASK. Синхронизация, аккаунты, MCP/Telegram, серверное расширение, App Store/деплой — будущие решения, не обязательная инфраструктура первого прототипа.

## Сохраняемые правила задач

Стабильный UUID, заголовок обязателен, trim, максимум500 Unicode code points; one-off complete/reopen. После добавления scheduling: planned date и deadline независимы, time только вместе с planned date; civil Gregorian даты не превращаются в UTC instant. Today buckets без дублей, Upcoming7 inclusive. Правила из принятых web TASK — спецификация для native, не заявление о готовом Swift-коде. Первый TASK не обязан реализовать все будущие поля заранее.

Local timezone по умолчанию из системной именованной зоны; отдельная настройка позже, без account dependencies. Без скрытой сетевой синхронизации. Ошибки открытия/сохранения storage видимы; не сбрасывать данные и не подменять failing persistent store пустым memory store.

## Приёмка первого шага NATIVE-001

Реальный macOS Inbox: ввод→Enter/add, complete/reopen, записи переживают закрытие и повторный запуск без сети. Синтетическое disk persistence test и наблюдаемый GUI flow. Сборка не доказывает GUI или iOS. Xcode установлен; iOS build и Simulator проверены в NATIVE-002, реальный iPhone пока не проверен. Приоритет iOS подтверждён пользователем; macOS R1 остаётся отдельной приостановленной коррекцией.

## Цель личного использования

Проверить основные сценарии на своих Apple-устройствах, затем14 дней ежедневного использования без потери данных. Экспорт/резервирование до переноса реальных важных задач — отдельный небольшой шаг перед длительным использованием. Не обещать обмен данными между iPhone и Mac до отдельной реализации/проверки sync.

## Продуктовая цель и навигация, уточнение 2026-10-13

Главная цель пользователя: удобный быстрый ввод и управление задачами как в Todoist, вместе с удобством календарного планирования как в TickTick. Календарь — основной сценарий продукта, а не второстепенное украшение. Liquid Glass — оформление элементов навигации/действий, не замена удобству задач.

Актуальный маршрут iPhone (прямое уточнение2026-10-14): Сегодня · Входящие · Предстоящее; Проекты появятся только с готовым экраном. Отдельной вкладки «Календарь» НЕТ. В «Сегодня» и «Предстоящем» пользователь переключает виды «Список / Календарь». Today привязан к текущему локальному дню, Предстоящее предназначено для просмотра/планирования дат. В календарном представлении Предстоящего будущие масштабы День/3 дня/Месяц; режим Неделя исключён. День и3дня используют вертикальную сетку времени, задачи занимают свои временные интервалы;3дня — три соседние колонки с одной шкалой, не три списка задач. Одинаковые задачи в разных видах, без копирования; выбор даты/фильтр сохраняются при смене календарного вида.

Пользователь одобрил общее визуальное направление интерактивного макета, уточнив календарные виды. Это одобрение концепта, не приёмка реализованных календарных функций: native scheduling/время/календарь ещё не реализованы. Дальнейшая реализация только небольшими отдельными заданиями; новая большая задача на весь календарь не выдаётся.

Уточнение2026-10-14 имеет приоритет над historical007B/007C assignments с отдельной Calendar tab. Принятая сетка остаётся переиспользуемым календарным представлением, не отдельным разделом продукта. Перестройка navigation/Today modes, затем real Upcoming list/calendar — два небольших отдельных TASK после review007C, перед duration/drag. Никаких пустых вкладок или переписывания store.
