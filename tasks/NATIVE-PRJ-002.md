# NATIVE-PRJ-002 — настоящий экран проектов

Статус: подготовлен, не запущен. База — main после интеграции NATIVE-PRJ-001 (точный SHA записать перед началом). Один результат: пользователь может создать и переименовать локальный проект на реальной четвёртой вкладке.

## Scope

- Добавить вкладку «Проекты» с реальным списком из принятого core, без фальшивого task-detail. Пустое состояние и видимые ошибки чтения/записи.
- Использовать тот же экземпляр store, что остальные вкладки. Не создавать второй container, отдельную БД или копии задач.
- Создание проекта — действие в шапке; общей FAB создания задач на «Проекты» нет. Тап/меню существующего проекта позволяет переименовать, но не открывает ещё не реализованный список его задач.
- Компактная общая create/rename форма с draft, Save/Cancel, валидатор core 1…120; успех только после save, отказ сохраняет draft/retry. Native themes, стабильный sheet host без предшествующей заливки, Dynamic Type.
- Никаких изменений core/schema, assignment, delete/archive, цвета/порядка/фильтра проектов, календарных исправлений или sync. Task assignment и реальный проектный список — PRJ003.

## Проверки

Один iOS build, GUI на своём Simulator с synthetic store: empty→create→rename, blank/overlimit→retry, Cancel/swipe без записи, tab round-trip, terminate/relaunch, dark/AXL smoke. Подтвердить UUID/createdAt при rename и неизменность task rows. Личный iPhone и базы не использовать для тестов. Все GUI interactions только поддержанным CUA; недоставленные жесты помечать UNVERIFIED. Сохранить отчёт/скриншоты вне product source, diff --check. Push/установка на устройство — только по актуальному разрешению пользователя.
